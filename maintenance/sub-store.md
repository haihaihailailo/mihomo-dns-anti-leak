# Sub-Store 维护设置

本说明基于 Sub-Store 2.39.8 已验证的原生设置，不包含私人组合、订阅 URL、缓存或认证信息。通过已登录管理页面/已授权原生 API 修改，服务运行时不要直接覆盖整个数据库文件。

## 合并单条订阅流量

组合订阅启用“合并单条订阅流量”，核对组合不再仅使用第一条来源流量（本版本对应 `firstSubFlow: false`），并按版本界面配置流量汇总处理。

参考 [xream 的 Sub-Store sum.js](https://github.com/xream/scripts/blob/main/surge/modules/sub-store-scripts/sub-info/sum.js)。已使用版本 SHA256：`8eeaaa87878e17b102922bc9145fd5d725b56c832bbcbfc13bb762ef02837d21`。上游链接会变化，执行前审查内容并核对哈希；不在此仓库镜像第三方脚本或自动下载执行。

刷新后同时比较导出响应的 `subscription-userinfo` 和保存的组合流量信息；保留各个来源自己的额度含义。没有返回流量字段的订阅不应伪造限额，也不能仅凭缺少字段判定节点不可用或套餐不限量。汇总显示不表示额度可以跨供应商共享。

对有临时下载开关的供应商，先开启开关再更新。关闭时的拒绝或旧缓存不等于所有来源失败；不要循环重试、泄露 URL token 或关闭证书验证。

## 清除提示条目

组合中用名称排除过滤删除到期/流量信息条目，允许前置 `【来源】`，英文大小写不敏感；这不是修改或删除原始单条订阅。示例正则的 English 部分用于名称过滤的“排除”模式：

```regex
^\s*(?:【[^】]*】\s*)?(?:[Tt][Rr][Aa][Ff][Ff][Ii][Cc]|[Ee][Xx][Pp][Ii][Rr][Ee]|[Ee][Xx][Pp][Ii][Rr][Yy]|[Ee][Xx][Pp][Ii][Rr][Aa][Tt][Ii][Oo][Nn])\s*[:：]
```

与现有中文提示过滤分别核对，避免把地区、协议或真实节点名当提示删除。导出后按来源统计真实节点，与单条订阅对比；公共策略组过滤代码已在本仓库生成器中维护。节点“存在”、延迟探测、真实代理流量和业务解锁需要分别验证。

## 初期日志与恢复

原生 `settings.logsMaxCount` 可从 300 调整至 10000，并通过 API/磁盘回读确认唯一字段变化及原日志保留；这按条数保留，不承诺固定天数或字节上限。已有 Docker `json-file` 日志轮转（例如 10m × 3）是另一层，修改应用日志无需重建容器。

先备份具体设置和数据库，由既有服务器备份体系登记路径、权限、哈希、容量预算与恢复方法；变更后检查容器健康、导出、保留事务与恢复演练。数据库含订阅凭据，备份仅在批准的私有位置保存，绝不能随本说明上传公开 Git。软件回滚材料和关键数据灾备按各自策略管理。
